ABSTRACT 
 
deessa Companion is an offline-capable, Nepali-language digital platform developed to 
support children with Autism Spectrum Disorder (ASD), their families, and caregivers 
in Nepal. It addresses the limited availability of affordable, accessible, and culturally 
appropriate autism support technologies for communication, learning, emotional well-
being, and progress monitoring. The system was developed using Agile methodology 
and follows a three-tier architecture comprising a native Android application using Java 
and XML, a Django REST Framework backend, and a Next.js administration panel. An 
offline-first approach using Room for local SQLite storage and WorkManager for 
synchronization enables core features during network interruptions. The application 
includes authentication, picture-based Augmentative and Alternative Communication 
(AAC), interactive learning, feelings and emotions, progress monitoring, rewards, and 
routine notifications. The AAC module provides 30 bilingual picture cards with audio 
support, while learning activities cover alphabets, sounds, shapes, numbers, and colors. 
The feelings module includes emotion check-ins, breathing exercises, meditation, 
calming music, and coloring activities. 
 
Testing demonstrated that the system met its functional and performance objectives, 
with 382 backend test cases and a complete pass rate for implemented Android unit 
tests. Overall, deessa Companion demonstrates the potential of an offline-first, 
multilingual platform to improve access to autism support resources and provide a 
practical foundation for technology-assisted care and learning in Nepal. 
Keywords: Autism Spectrum Disorder, Augmentative and Alternative Communication 
(AAC), Nepali Language, Offline-First, Mobile Application, Android, Django, 
Accessibility, Child Development.

CHAPTER 1 : INTRODUCTION 
1.1 Background 
Autism Spectrum Disorder (ASD) is a neurodevelopmental condition that can affect 
communication, social interaction, behavior, and learning. According to the World 
Health Organization (WHO), approximately one in 100 children worldwide is affected 
by autism, highlighting the need for accessible and continuous support for children with 
autism and their families. 
In Nepal, families of children with autism may face challenges related to access to 
specialized services, affordability, language, geographical location, and availability of 
suitable learning and communication resources. Professional services are concentrated 
mainly in urban areas, creating additional difficulties for families in other regions. 
Technology can provide support through Augmentative and Alternative 
Communication (AAC), structured learning activities, emotional-support tools, and 
progress monitoring. However, many existing solutions are designed for international 
users and may not adequately address the linguistic, cultural, financial, and connectivity 
conditions of Nepali families. 
Reliable internet connectivity is also not uniform across Nepal. Therefore, applications 
that depend entirely on continuous internet access may provide limited support in areas 
with unstable connectivity. An offline-capable approach can help maintain access to 
essential communication and learning features when internet connectivity is 
unavailable. 
To address these needs, deessa Companion was developed in collaboration with the 
deessa Foundation as a mobile-based autism support and learning platform for the 
Nepali context. The application follows an offline-first approach and focuses on 
communication, learning, and progress tracking, with additional features for feelings 
and emotions, rewards, routines, notifications, and caregiver support. It is intended to 
complement professional therapy, medical care, and educational intervention by 
providing accessible tools for children and their caregivers in everyday environments.

The purpose of deessa Companion is to provide an accessible and user-friendly digital 
support platform for children with Autism Spectrum Disorder and their parents or 
caregivers in Nepal. The application is designed for use in everyday and home-based 
environments to support communication, learning, emotional activities, and progress 
monitoring.

1.3.2.1 Android Mobile Application 
The Android application is primarily designed for children with autism and their parents 
or caregivers. It provides separate parent-oriented and child-oriented experiences. 
The parent interface provides five main navigation areas: 
 Home: Dashboard, child selection, schedules, notifications, and care-related 
information. 
 Talk: Picture-based AAC cards with categories, bilingual labels, audio 
playback, search, filtering, favorites, and usage information. 
 Learn: Interactive activities covering Color Match, Shape Explorer, Count & 
Learn, Alphabet Fun, and Animal Sounds. 
 Progress: Activity statistics, progress information, trends, reports, milestones, 
and achievements. 
 Profile: Child and caregiver management, schedules, medications, emergency 
contacts, account settings, language preferences, and notifications. 
The application also provides a protected Child Mode with a simplified interface 
focused on Talk, Learn, Feelings, and Rewards. A parent-controlled PIN separates 
child-oriented activities from parent management functions. 
 
1.3.2.2 Backend REST API 
The backend is implemented using Django and Django REST Framework (DRF) . It 
provides server-side services for authentication, child and parent profiles, AAC content, 
learning activities, emotions, routines, medications, rewards, progress, notifications, 
synchronization, audit logging, and analytics. SQLite is used during development, 
while PostgreSQL is intended for production deployment. 
 
1.3.2.3 Web Admin Panel 
The web-based administrative panel is developed using Next.js, React, TypeScript, and 
Tailwind CSS. It allows authorized administrators to manage application content and 
system data, including AAC cards, learning activities, rewards, users, child-related 
information, and analytics.

CHAPTER 2 : SURVEY AND REVIEWS 
2.1 Literature Survey 
Technology has increasingly been used to support individuals with Autism Spectrum 
Disorder (ASD) in areas such as communication, learning, engagement, and progress 
monitoring. Previous research has explored Augmentative and Alternative 
Communication (AAC), mobile applications, offline-capable systems, and 
gamification. These studies provide the foundation for the design of deessa Companion 
and highlight the importance of accessibility, localization, usability, and reliable access. 
 
2.1.1 Augmentative and Alternative Communication (AAC) 
 
Light and McNaughton (2012) emphasized the role of Augmentative and Alternative 
Communication (AAC) in supporting individuals with complex communication needs. 
Beukelman and Light (2020) further discussed the development of AAC from 
traditional communication boards to digital speech-generating systems, highlighting 
the importance of simple navigation, personalization, consistent interfaces, and suitable 
vocabulary. 
These findings support the picture-based AAC module in deessa Companion, which 
uses categorized communication cards, bilingual labels, and audio feedback to provide 
an accessible communication method for children with speech-related difficulties. 
 
2.1.2 Mobile Applications for Autism Support 
 
Walsh et al. (2017) reviewed mobile applications for autism and identified 
communication and social-skill support as major application areas. Laski et al. (2018) 
also reported positive communication-related outcomes from tablet-based picture 
communication applications and highlighted the importance of visual consistency, 
audio feedback, and age-appropriate content. 
These findings demonstrate the potential of mobile technology to provide portable 
autism support. deessa Companion applies these principles through a child-friendly 
interface, Nepali and English content, visual communication cards, audio feedback, and 
structured learning activities.

8 
2.1.3 Offline-First and Low-Connectivity Solutions 
 
Brewer et al. (2015) emphasized the importance of systems that can continue providing 
essential functionality during network interruptions. Ratanasanyasak et al. (2020) 
highlighted local data storage, synchronization, and graceful handling of connectivity 
loss when designing mobile systems for low-connectivity environments. 
These findings are relevant to deessa Companion because its core features are designed 
to remain accessible without continuous internet connectivity. Local storage and 
synchronization support continuity of use and data synchronization when connectivity 
is restored.  
 
2.1.4 Gamification in Education 
Deterding et al. (2011) described gamification as the use of game-design elements in 
non-game contexts, including points, badges, and progress indicators. Hamari et al. 
(2014) found that gamification can improve engagement and motivation, although its 
effectiveness depends on appropriate implementation. 
deessa Companion uses stars, badges, milestones, and reward streaks as supporting 
mechanisms to encourage participation in learning activities while keeping learning and 
skill development as the primary objectives. 
2.1.5 Technology for Autism in Developing Countries 
Research on autism-support technologies in developing countries identifies language, 
culture, affordability, accessibility, and connectivity as important design 
considerations. El Ghazali et al. (2018) emphasized localization and cultural context, 
while Khan (2019) discussed challenges in autism support in countries including Nepal 
and highlighted the potential of mobile technology to extend access to support. 
These findings support the need for a localized solution for Nepal. deessa Companion 
addresses these considerations through bilingual content, offline-capable functionality, 
child-friendly interfaces, AAC communication, structured learning, and parent-oriented 
progress monitoring.

Families of children with Autism Spectrum Disorder (ASD) in Nepal face difficulties 
in accessing affordable, localized, and accessible digital support for communication, 
learning, emotional well-being, and progress monitoring. Existing solutions often focus 
on specific areas, provide limited Nepali-language support, or depend on continuous 
internet connectivity.

preferences. Affordable picture-based AAC resources with Nepali support are 
limited.

need structured learning, emotional-support, and calming activities that can be 
used at home and are appropriate for the local context. 
 Connectivity and accessibility constraints: Uneven internet availability and 
the cost or geographical limitations of specialized services can reduce access 
to continuous support. 
 Progress and caregiver management gap: Caregivers need convenient tools 
to monitor learning and emotional progress while managing routines, 
schedules, medications, and other everyday needs.

CHAPTER 7 : CONCLUSION 
7.1 Conclusion 
The deessa Companion project developed a mobile-based support system for children 
with Autism Spectrum Disorder (ASD) and their parents or caregivers in the Nepali 
context. The system integrates AAC communication, learning activities, feelings and 
emotional-support tools, progress monitoring, routines, and rewards within a single 
platform. 
The system consists of three main components: a native Android application for 
children and parents, a Django REST API backend for application data and services, 
and a Next.js administration panel for managing users and application content. 
The project emphasizes Nepali and English language support, offline-capable 
functionality, child-friendly interaction, and parent-centered management. The 
completed implementation provides a practical foundation for localized digital autism 
support while allowing future expansion through additional content, services, and 
integrations. 
7.1.1 Significance of the System 
The significance of deessa Companion can be summarized as follows: 
 Linguistic Accessibility:  Supports both Nepali and English for improved 
accessibility.  
 Offline-Capable Design: Allows important locally stored features to remain 
available without continuous internet connectivity.  
 Integrated Support: Combines communication, learning, emotional support, 
progress tracking, routines, and rewards in one platform.  
 Parent-Centered Management:  Provides tools for managing child profiles, 
routines, medications, emergency information, and related activities.  
 Child-Friendly Interaction:  Provides a simplified Child Mode with Talk, 
Learn, Feelings, and Rewards features.  
 Progress and Motivation:  Uses progress information, activity history, stars, 
and badges to support monitoring and positive reinforcement.  
 Extensible Architecture: The modular architecture provides a foundation for 
future content, synchronization, professional collaboration, and additional 
languages.  
Overall, the project provides a functional and localized foundation for digital autism 
support, with further improvement possible through continued testing, content 
expansion, and additional services.

7.2 Limitations of the System 
The current implementation has the following limitations: 
 Cloud Synchronization:  Comprehensive cloud backup and cross-device 
synchronization are not fully implemented.  
 Limited AAC Content: The current AAC library provides a basic vocabulary 
and does not yet include advanced sentence-building capabilities.  
 Limited Learning Content:  The system currently provides five primary 
learning activity types, with scope for additional subjects and adaptive 
difficulty.  
 Multi-Device Support:  Seamless access to the same child's data across 
multiple devices is not currently available.  
 Offline Export:  Comprehensive offline data export and external sharing 
features are not currently available.  
 Language Limitation: The application currently supports Nepali and English 
only.  
 Basic Analytics: Current analytics focus mainly on activity completion, scores, 
usage, and milestones rather than advanced predictive analysis.  
 Professional Integration:  Dedicated therapist and teacher interfaces are not 
part of the current implementation.  
 Community Features: Parent-to-parent social and community features are not 
currently provided.

classroom-based support.

@action(detail=True, methods=['post']) 
def complete(self, request, pk=None): 
    progress = self.get_object() 
    if progress.status != 'in_progress': 
        raise ValidationError('Activity is not in progress.') 
    serializer = ActivityProgressCompleteSerializer(data=request.data) 
    serializer.is_valid(raise_exception=True) 
    questions = list(activity.questions.all()) 
    questions_by_id = {str(q.id): q for q in questions} 
    answer_results = [] 
 
    for item in serializer.validated_data.get('answers', []): 
        question = questions_by_id.get(str(item['question_id'])) 
        if not question: continue 
        correct = ScoringEngine.check_answer(question, item.get('answer','')) 
        answer_results.append({'question_id': str(item['question_id']), 
            'answer': item.get('answer'), 'correct': correct}) 
    result = ScoringEngine.evaluate_completion( 
        progress, questions, answer_results, 
        time_spent=serializer.validated_data.get('time_spent')) 
    progress.score = result['score'] 
    progress.correct_answers = result['correct_answers'] 
    progress.total_questions = result['total_questions'] 
    progress.save() 
 
    stars_earned = result['stars_earned'] 
    if stars_earned > 0: 
        existing = ActivityProgress.objects.filter( 
            child=progress.child, activity=activity, 
            status='completed', passed=True 
        ).exclude(pk=progress.pk).order_by('-score').first() 
        if existing and result['score'] <= existing.score: 
            stars_earned = 0 
 
    return Response({'id': str(progress.id), 'score': progress.score, 
        'passed': progress.passed, 'stars_earned': stars_earned, 
        'badges_earned': [{'badge_id': str(cb.badge_id), 
            'badge_name': cb.badge.name_en} for cb in badges_earned]})

public LiveData<Resource<BaseResponse>> verifyChildModePin( 
        ChildModePinVerifyRequest request) { 
    MutableLiveData<Resource<BaseResponse>> liveData = new 
MutableLiveData<>(); 
    liveData.setValue(Resource.loading()); 
    apiService.verifyChildModePin(request).enqueue(new Callback<>() { 
        public void onResponse(Call c, Response r) { 
            if (r.isSuccessful()) { 
                cachePinHashLocally(request.getPin()); 
                liveData.setValue(Resource.success(r.body())); 
            } else liveData.setValue(Resource.error("Invalid PIN")); 
        } 
    });
